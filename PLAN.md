# PLAN.md

Migration plan for LUMEN: from static SCSS/HTML to Hugo + UnoCSS +
htmx + _hyperscript.

## 1. Target Stack

| Layer         | Current                 | Target                          |
|---------------|-------------------------|---------------------------------|
| Site engine   | Static HTML             | Hugo                            |
| Styling       | SCSS (hand-compiled)    | UnoCSS CLI (atomic + shortcuts) |
| Interactivity | _hyperscript (CDN)      | _hyperscript (CDN, unchanged)   |
| Transport     | htmx (fragment loading) | htmx (Hugo partials + AJAX)     |
| Icons         | Boxicons (CDN)          | UnoCSS preset-icons (pure CSS)  |
| Colour scheme | Frankifuscus Base16     | UnoCSS theme (same palette)     |

## 3. UnoCSS Configuration

### 3.1 Theme — Frankifuscus Base16

Map the existing SCSS variables to UnoCSS theme colours so that
utilities like `bg-base00`, `text-base0B`, `border-base00` work
automatically:

```typescript
// uno.config.ts
import { defineConfig, presetWind3, presetIcons } from 'unocss'

export default defineConfig({
  presets: [
    presetWind3(),
    presetIcons({ scale: 1.2, cdn: 'https://esm.sh/' }),
  ],
  theme: {
    colors: {
      base00: '#000000',
      base01: '#0C0C0B',
      base02: '#242321',
      base03: '#43423E',
      base04: '#6A6862',
      base05: '#96948B',
      base06: '#C8C4B8',

      base08: '#F8A8B2',
      base09: '#F8B28A',
      base0A: '#F8DA8A',
      base0B: '#DAF88A',
      base0C: '#8AF8D2',
      base0D: '#8AD2F8',
      base0E: '#C28AF8',

    },
  },
  content: {

  },
})
```

### 3.2 Shortcuts — Neobrutalist Primitives

Define reusable component shortcuts that encode the neobrutalist
design language (bold borders, solid shadows, flat colours):

```typescript
shortcuts: {
  // Borders
  'neo-border':        'border-1 border-base00 border-solid',
  'neo-border-strong': 'border-2 border-base00 border-solid',

  // Shadows
  'neo-shadow':        'shadow-[3px_3px_0_0_#000]',
  'neo-shadow-lg':     'shadow-[4px_4px_0_0_#000]',

  // Hover lift
  'neo-lift':          'transition-all duration-200 hover:translate-x--0.5 hover:translate-y--0.5 hover:neo-shadow-lg',
  'neo-lift-y':        'transition-all duration-200 hover:translate-y--1.25',

  // Base component shapes
  'neo-card':          'neo-border rounded-2 bg-base07 text-base00 p-[0.35rem_0.75rem]',
  'neo-card-strong':   'neo-border-strong neo-shadow-lg rounded-2 bg-base07 text-base00 p-[0.35rem_0.75rem]',
  'neo-pill':          'neo-border rounded-full px-3 py-1.5 font-500 text-center text-base00',
  'neo-btn':           'neo-border rounded-0.5 px-5 py-2.5 font-500 cursor-pointer neo-lift',
  'neo-btn-strong':    'neo-border-strong rounded-0.5 px-5 py-2.5 font-500 cursor-pointer neo-shadow',
}
```

### 3.3 Build Pipeline

```jsonc
// package.json (minimal)
{
  "devDependencies": {
    "unocss": "latest"
  },
  "scripts": {
    "css:dev":   "unocss --watch -o assets/css/uno.css",
    "css:build": "unocss -o assets/css/uno.css",
    "dev":       "npm run css:dev & hugo server",
    "build":     "npm run css:build && hugo --minify"
  }
}
```

UnoCSS CLI scans `layouts/` and `content/`, generates
`assets/css/uno.css`, and Hugo picks it up via its asset pipeline.

### Phase 1 — Port Existing Components (7)

Migrate each existing component one at a time. For each:

- [ ] Create Hugo shortcode in `layouts/_shortcodes/`.

Order: button → card → alert → badge → avatar → accordion →
breadcrumb (roughly from simplest to most interactive).

dependency and utility:

1. **Layout first:** container, divider, hero.

   dropdown.
3. **Forms:** input, textarea, select, checkbox, radio, toggle,
   file-upload, form-group.
4. **Data display:** table, list, tag, tooltip, popover, stat, kbd.
5. **Feedback:** toast, modal, progress, spinner, skeleton.

## 6. Design Decisions

### Why UnoCSS instead of keeping SCSS?

The current SCSS variables and component styles are essentially
re-implementing a utility system by hand. UnoCSS provides the same
design-token-driven approach with zero custom CSS to maintain, better
tree-shaking (only used utilities are emitted), and a richer
ecosystem (icons, attributify, inspector).

### Why Hugo?

Hugo renders the component showcase and documentation as a static
site. It provides partials (for component fragments), shortcodes (for
inline demos in Markdown), and a built-in asset pipeline. No runtime
server is required, and build times are sub-second.

### Why keep htmx and _hyperscript?

They are the interaction layer, not the styling layer. htmx handles
server-driven fragment loading (useful for dynamic demos, AJAX
patterns). _hyperscript handles client-side DOM manipulation
(accordion toggles, dismissals, modals). Neither conflicts with the
SCSS → UnoCSS migration; they operate on the HTML, not the CSS.

### Icons: Boxicons CDN → UnoCSS preset-icons

UnoCSS preset-icons renders icons as pure CSS (no external CDN
request, no flash of unstyled icons). The Boxicons set is available
via `@iconify-json/bx`. Class syntax changes from
`class="bx bxs-cart"` to `class="i-bx-cart"`.
